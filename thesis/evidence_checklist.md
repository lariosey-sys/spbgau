# Checklist фактических материалов для защиты

Этот файл отделяет уже написанную проектную часть от материалов, которые нужно получить при запуске оборудования или финальной сборке ВКР.

Подробный сценарий проверки приведен в `thesis/test_protocol.md`.

Для сбора текстовых артефактов запуска используется `thesis/collect_evidence.sh`. Результаты сохраняются в `thesis/evidence/<timestamp>/`.

## Уже подтверждается текущим репозиторием

| Требование | Доказательство |
|---|---|
| Есть прошивка датчика температуры и влажности | `Greenhouse/firmware/sensor_th/sensor_th.ino` |
| Есть прошивка датчика CO2 | `Greenhouse/firmware/sensor_co2/sensor_co2.ino` |
| Есть прошивка контроллера 15 реле | `Greenhouse/firmware/greenhouse_mega/greenhouse_mega.ino` |
| Используется MQTT-модель обмена | MQTT-топики в прошивках и `Greenhouse/dashboard/app.py` |
| Есть Flask-dashboard | `Greenhouse/dashboard/app.py` |
| Есть контейнерная конфигурация | `Greenhouse/docker-compose.yml` |
| Есть SQLite-схема истории | функции создания `sensor_log` и `relay_log` в `Greenhouse/dashboard/app.py` |
| Есть правила автоматизации | блок rules в `Greenhouse/dashboard/app.py` |
| Есть профили вентиляции | блок profiles в `Greenhouse/dashboard/app.py` |
| Есть экспорт истории | `/api/export/<data_type>` в `Greenhouse/dashboard/app.py` |
| Есть корпус литературы | `literature/`, `literature/references.bib`, `literature/literature_matrix.md` |
| Есть черновик основных частей ВКР | `thesis/introduction.md`, главы 1-3, `thesis/conclusion.md` |

## Нужно решить перед финальной сдачей

| Вопрос | Варианты решения |
|---|---|
| Будет ли фактический ML-эксперимент | выполнить baseline/ML на накопленных данных или оставить раздел как подготовку эксперимента |
| Какой формат ссылок требует кафедра | заменить служебные citation keys на нумерованные ссылки или ГОСТ-стиль |
| Нужно ли включать полные листинги | включить в приложения целиком или дать ключевые фрагменты |
| Как оформлять онлайн/preprint источники | вручную вычитать `literature/references_gost_draft.md` |
| Как назвать тему финально | оставить текущую или согласовать формулировку с научруком |

## Минимальный набор для убедительной защиты

1. Скриншот dashboard с текущими значениями датчиков.
2. Скриншот или видео переключения одного реле через веб-панель.
3. Пример MQTT-телеметрии от обоих датчиков.
4. Пример записи в `sensor_log`.
5. Пример записи в `relay_log`.
6. Таблица MQTT-топиков.
7. Таблица реле и исполнительных устройств.
8. Список литературы в финальном формате.
