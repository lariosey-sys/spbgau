# План ML-эксперимента для данных теплицы

Документ описывает реалистичный эксперимент, который можно выполнить поверх текущей реализации `Greenhouse/` после накопления телеметрии.

## Цель

Проверить, пригодны ли данные, собираемые системой мониторинга теплицы, для краткосрочного прогноза параметров микроклимата. Основной результат эксперимента - не автономное управление, а доказательство, что архитектура сбора данных поддерживает будущий интеллектуальный слой.

## Исходные данные

Основные таблицы:

| Таблица | Использование |
|---|---|
| `sensor_log` | временные ряды температуры, влажности и CO2 |
| `relay_log` | события включения и выключения исполнительных устройств |

Поля `sensor_log`:

| Поле | Роль |
|---|---|
| `ts` | временная метка |
| `device` | источник измерения |
| `temperature` | целевая переменная или признак |
| `humidity` | целевая переменная или признак |
| `co2` | целевая переменная или признак |

Поля `relay_log`:

| Поле | Роль |
|---|---|
| `ts` | временная метка события |
| `relay_id` | номер исполнительного канала |
| `state` | состояние реле после события |

## Задачи прогнозирования

Минимальный набор задач:

1. Прогноз температуры через 10, 30 и 60 минут.
2. Прогноз влажности через 10, 30 и 60 минут.
3. Прогноз CO2 через 10, 30 и 60 минут.

Дополнительные задачи после накопления большего датасета:

1. Прогноз выхода параметра за допустимый диапазон.
2. Оценка реакции микроклимата на включение вентиляторов, заслонок или ТЭНов.
3. Рекомендация включения профиля на основе прогноза.

## Подготовка датасета

1. Выгрузить данные из `/api/export/sensors` и `/api/export/relays` либо напрямую из SQLite.
2. Привести `ts` к единому datetime-формату.
3. Развернуть сенсорные данные в wide-формат: отдельные колонки для `th-1_temperature`, `th-1_humidity`, `co2-1_temperature`, `co2-1_humidity`, `co2-1_co2`.
4. Привести данные к равномерному шагу 1 минута.
5. Синхронизировать события реле с минутной шкалой и получить бинарные признаки `relay_1` ... `relay_15`.
6. Заполнить короткие пропуски интерполяцией или переносом последнего значения.
7. Удалить интервалы с длинными пропусками и явно некорректными значениями.

## Признаки

Базовые признаки:

| Группа | Примеры |
|---|---|
| Текущие измерения | температура, влажность, CO2 |
| Лаги | значения 1, 5, 10, 30 и 60 минут назад |
| Скользящие агрегаты | среднее, минимум, максимум, стандартное отклонение за 10/30/60 минут |
| Время | час, минута, день недели, признак ночь/день |
| Исполнительные устройства | состояния реле 1-15 |
| Недавние события | время с последнего включения вентилятора/ТЭНа/заслонки |

Перспективные внешние признаки:

| Признак | Зачем нужен |
|---|---|
| наружная температура | объясняет теплопотери и перегрев |
| солнечная радиация/освещенность | влияет на нагрев и фотосинтез |
| влажность наружного воздуха | влияет на вентиляцию |
| фаза роста культуры | влияет на целевые режимы |

## Целевые переменные

Для горизонта `H` минут:

| Target | Формула |
|---|---|
| `temperature_t_plus_H` | температура через `H` минут |
| `humidity_t_plus_H` | влажность через `H` минут |
| `co2_t_plus_H` | CO2 через `H` минут |

Для классификационной постановки:

| Target | Формула |
|---|---|
| `temperature_out_of_range_H` | температура выйдет за допустимый диапазон в ближайшие `H` минут |
| `humidity_out_of_range_H` | влажность выйдет за допустимый диапазон в ближайшие `H` минут |
| `co2_out_of_range_H` | CO2 выйдет за допустимый диапазон в ближайшие `H` минут |

## Модели

Baseline:

| Модель | Назначение |
|---|---|
| Last value | прогноз равен последнему наблюдению |
| Moving average | прогноз равен среднему за последние N минут |
| Linear regression | простая интерпретируемая модель |

Основные модели:

| Модель | Назначение |
|---|---|
| Random Forest / Gradient Boosting | табличные признаки, устойчивый baseline ML |
| XGBoost/LightGBM или аналог | сильная модель для табличных временных признаков |
| LSTM/GRU | последовательностная модель при достаточном объеме данных |
| TCN/Transformer | перспективный вариант после расширения датасета |

Для ВКР рационально начать с baseline и табличной ML-модели. LSTM/GRU стоит описывать как следующий уровень, если объем данных недостаточен для надежного обучения.

## Валидация

Разделение должно учитывать время:

1. Не перемешивать строки случайно.
2. Использовать первые 70% периода для обучения, следующие 15% для валидации, последние 15% для теста.
3. Проверить качество отдельно для дневных и ночных интервалов.
4. Сравнить модели с baseline, а не только между собой.

Метрики:

| Задача | Метрики |
|---|---|
| Регрессия | MAE, RMSE, R2 |
| Классификация выхода за диапазон | precision, recall, F1 |

## Минимальный критерий успеха

Эксперимент можно считать успешным, если:

1. Сформирован воспроизводимый датасет из `sensor_log` и `relay_log`.
2. Есть baseline-прогноз для каждого целевого параметра.
3. ML-модель превосходит baseline хотя бы по одной целевой переменной и одному горизонту.
4. Ошибки проанализированы по времени суток и режимам оборудования.
5. Показано, какие дополнительные датчики или признаки нужны для повышения качества.

## Ограничения

Текущая система не содержит наружную погоду, освещенность, тип культуры, фазу роста и фактические агрономические результаты. Поэтому прогноз микроклимата можно ставить раньше, чем прогноз урожайности или оптимальное управление. Выводы о ML-качестве должны быть ограничены локальной теплицей и периодом сбора данных.

## Связь с ВКР

В тексте диплома этот эксперимент можно использовать в разделе 3.5 или вынести в отдельный подраздел практической части. Он связывает инженерную реализацию с темой машинного обучения: система не просто отображает датчики, а собирает структуру данных, из которой можно получить прогнозную модель.
