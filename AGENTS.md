# AGENTS.md

Этот файл задает рабочие правила для дальнейшего ведения ВКР по теплице.

## Главная рамка

Тема ВКР: «Разработка и внедрение интеллектуальной системы управления микроклиматом в теплице на основе машинного обучения для повышения эффективности выращивания растений».

Работу нужно вести как магистерскую ВКР про **расширяемую IoT/ML-платформу управления микроклиматом теплицы**, а не как простой проект «датчик + реле + dashboard».

Ключевая формулировка результата:

> разработан прототип расширяемой программно-аппаратной IoT/ML-платформы, обеспечивающей подключение разнородных датчиков, управление исполнительными устройствами, журналирование истории и подготовку данных для машинного обучения.

## Источники истины

Рабочие управляющие документы:

1. `thesis/vkr_architectural_plan.md` - исследовательская рамка, новизна, главы, ожидаемые результаты.
2. `thesis/vkr_execution_plan.md` - этапы выполнения и page budget.
3. `thesis/work_progress.md` - живой чеклист и журнал изменений.
4. `thesis/quality_audit.md` - остаточные риски готовности.
5. `thesis/reference_mifi_vkr/README.md` - только пример оформления, не источник содержания.
6. `thesis/formatting_rules.md` - текущие правила LaTeX/PDF-оформления ВКР.

При начале новой существенной работы сначала сверяться с `thesis/work_progress.md`, затем обновлять статус после выполненных изменений.

## Основной формат работы

Вся ВКР ведется через LaTeX. Основной рабочий и финальный формат - связка `thesis/assembled_draft_numbered.tex` + `thesis/assembled_draft_numbered.pdf`, собираемая скриптом `bash thesis/export_draft.sh`.

DOCX/HTML могут использоваться только как дополнительные производные форматы для просмотра или передачи текста. Приоритет при проверке структуры, оформления, нумерации, оглавления, списков, таблиц, рисунков и библиографии всегда у LaTeX/PDF.

## Reference МИФИ

Папка `thesis/reference_mifi_vkr/` содержит только пример того, как может выглядеть готовая ВКР. Ее нельзя использовать как источник содержательных формулировок для текущей темы. Допустимо использовать:

- порядок служебных разделов;
- пример плотности текста;
- пример оглавления;
- пример визуального оформления PDF;
- LaTeX/PDF-верстку последней эталонной сборки `thesis/reference_mifi_vkr/latex/87_ВКР_латех.pdf`;
- шаблоны как ориентир, если они совместимы с требованиями текущей кафедры.

## Текущая научная линия

Новизна должна формулироваться через:

1. расширяемую IoT/ML-архитектуру;
2. подключение разнородных датчиков через единую модель обмена;
3. совместную регистрацию микроклимата и управляющих воздействий;
4. подготовку датасета для ML-прогнозирования реакции теплицы;
5. гибридный контур: правила/профили как безопасный нижний уровень, ML как верхний прогнозный слой.

Не заявлять новый ML-алгоритм, если он не разработан. Не заявлять завершенное ML-управление, если нет фактического эксперимента.

## Правила редактирования

1. Не запускать Docker, сервисы, dashboard или инфраструктуру без прямого запроса пользователя.
2. Не устанавливать зависимости и не тянуть образы без прямого запроса пользователя.
3. Для литературной работы работать только с `literature/` и текстами `thesis/`.
4. После каждого крупного изменения обновлять `thesis/work_progress.md`.
5. Основной формат написания и финальной сборки ВКР - LaTeX с PDF-выводом. Правила оформления зафиксированы в `thesis/formatting_rules.md`. После изменения текстов ВКР проверять сборку через `bash thesis/export_draft.sh`; скрипт должен формировать не только DOCX/HTML, но и `thesis/assembled_draft_numbered.tex` + `thesis/assembled_draft_numbered.pdf`.
6. Не смешивать материалы reference МИФИ с текущим содержанием.

## Ближайший курс работы

1. Обновить введение под платформенную рамку.
2. Переписать/дополнить главу 2 разделами про расширяемость.
3. Обновить заключение.
4. Усилить главу 1 источниками про расширяемые smart greenhouse платформы, heterogeneous sensors и data fusion.
5. После появления реальных данных выполнить минимальный ML-эксперимент.
