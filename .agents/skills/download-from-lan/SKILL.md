<objective>
Скачать полную книгу с платформы «Лань» как один валидный PDF, без почастичной выгрузки по 25 страниц печати.
</objective>

<key_insight>
Кнопки «Скачать» на Лани нет, а диалог «Печать/Сохранить» ограничивает выгрузку 25 страницами за раз и имеет дневной лимит. Но веб-ридер (`reader.lanbook.com/book/<ID>`) построен на PDF.js, который при открытии книги целиком загружает PDF через внутренний эндпоинт. Этот эндпоинт отдаёт полный незашифрованный PDF — его можно забрать напрямую из авторизованной сессии браузера.

Эндпоинт:
```
/api/v2/book/<BOOK_ID>/documentFile?base64=1&lms=
```
возвращает JSON `{"data": "<base64 PDF>"}`. Куки и JWT подставляются автоматически из сессии пользователя — отдельная авторизация не нужна, если пользователь уже вошёл в Лань в окне браузера.
</key_insight>

<prerequisites>
- Отдельный видимый Chrome с изолированным профилем `books` и remote-debugging (CDP). Это НЕ обычный Chrome пользователя и НЕ безголовый браузер агента — см. «Управление браузером» ниже.
- Пользователь САМ авторизован в Лани в этом окне Chrome (вошёл в личный кабинет на e.lanbook.com). Агент не вводит логин/пароль — он подключается к уже залогиненному окну через CDP и работает в той же сессии.
- ID книги из URL ридера: `reader.lanbook.com/book/<ID>`.
- Папка для сохранения, по умолчанию `~/MyProjects/spbgau/literature/books/`.
</prerequisites>

<browser_management>
## Управление браузером с залогиненной сессией

Для скачивания с Лани нужен **отдельный видимый Chrome**, в котором пользователь вручную входит в свой аккаунт. Агент подключается к этому окну как наблюдатель/оператор через протокол CDP (Chrome DevTools Protocol) — тот же механизм, что использует Playwright/Puppeteer.

### Зачем отдельный браузер

- **Изоляция сессии.** Используется собственный user-data-dir (`~/MyProjects/spbgau/.browser_profile`, профиль `books`), не пересекающийся с обычным Chrome пользователя. Куки, JWT и история Лани живут только в нём.
- **Сохранение логина.** Профиль постоянный — после первого входа в Лань пользователь не должен авторизоваться заново в следующих сеансах. Кука `lan_access_token` и `lan_refresh_token` переживают перезапуск Chrome.
- **Видимость.** Окно видно на экране — пользователь видит, что агент открывает, может сам заходить в кабинет, открывать книги, проверять доступ.

### Роли

- **Пользователь** — заходит в Лань в окне этого Chrome, открывает нужные книги, при необходимости обновляет доступ. Это единственный, кто вводит учётные данные.
- **Агент** — подключается к запущенному Chrome по CDP, читает URL открытых вкладок, выполняет JS на страницах, триггерит скачивание. Не имеет доступа к паролям и не выполняет авторизацию за пользователя.

### Запуск Chrome с CDP

1. Создать папку профиля (один раз): `~/MyProjects/spbgau/.browser_profile`.
2. Запустить Chrome в фоне с remote-debugging:
   ```
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --user-data-dir="/Users/sergei/MyProjects/spbgau/.browser_profile" \
     --profile-directory=books \
     --remote-debugging-port=9222 \
     --no-first-run --no-default-browser-check about:blank
   ```
3. Chrome сам выбирает свободный порт, если 9222 занят — найти его: `pgrep -lf "remote-debugging-port"`.
4. Подключиться инструментом `browser` (`action: open`, `app.cdp_url: http://127.0.0.1:<PORT>`). После этого доступны `browser.pages()`, `page.evaluate()`, `page.target().createCDPSession()` и т.д.

### Первый вход в Лань

После запуска попросить пользователя:
1. Открыть `https://e.lanbook.com` в окне этого Chrome.
2. Войти в личный кабинет (кнопка «Вход», логин/пароль или доступ через вуз).
3. Дождаться, пока в cookie появится `lan_access_token` (можно проверить через `browser.cookies()`).

После этого сессия готова — агент может открывать ридеры книг и скачивать их.

### Если Chrome уже запущен

Если в `pgrep` виден процесс `Google Chrome --remote-debugging-port=<N>` с тем же `--user-data-dir`, повторно запускать НЕ надо — просто подключиться по найденному порту. Повторный запуск с тем же профилем приведёт к закрытию первого окна.

### Завершение

По окончании работы Chrome можно оставить запущенным (логин сохранится) или закрыть. Профиль на диске остаётся; при следующем запуске с тем же `--user-data-dir` сессия Лани восстанавливается автоматически.

<process>

## 1. Запуск браузера и авторизация

См. раздел `<browser_management>` выше. Кратко:
- Запустить Chrome с CDP (если ещё не запущен).
- Подключиться инструментом `browser` по CDP.
- Убедиться, что пользователь авторизован в Лани (в cookie есть `lan_access_token`). Если нет — попросить пользователя войти в окне Chrome.

Браузер и сессия сохраняются между книгами и между сеансами — повторная авторизация нужна только при истечении JWT.

## 2. Получить ID книги

Из URL читалки: `https://reader.lanbook.com/book/455561...` → `BOOK_ID = 455561`.

Если пользователь дал ссылку на карточку книги `e.lanbook.com/...`, попросить его открыть книгу в ридере (кнопка «Читать»), и взять ID из URL.

## 3. Открыть ридер книги

Перейти на `https://reader.lanbook.com/book/<BOOK_ID>`. Дождаться загрузки PDF.js (появления тулбара с `#pageNumber` и `#pageTotal`). Это гарантирует, что JWT-токен сессии активен и эндпоинт `documentFile` отдаст данные, а не 401.

## 4. Настроить папку загрузки через CDP

На странице ридера создать CDP-сессию и задать путь загрузки:
```js
const client = await reader.target().createCDPSession();
await client.send('Page.setDownloadBehavior', {
  behavior: 'allow',
  downloadPath: '/Users/sergei/MyProjects/spbgau/literature/books'
});
```
Без этого blob-скачивание упадёт в `~/Downloads`, а не в целевую папку.

## 5. Скачать и сохранить PDF

Выполнить на странице ридера (куки и JWT применяются автоматически):
```js
const result = await reader.evaluate(async () => {
  const url = `/api/v2/book/${BOOK_ID}/documentFile?base64=1&lms=`;
  const resp = await fetch(url, { credentials: 'include' });
  const j = await resp.json();
  const bin = atob(j.data);                       // base64 → бинарная строка
  const bytes = new Uint8Array(bin.length);
  for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
  const blobUrl = URL.createObjectURL(new Blob([bytes], { type: 'application/pdf' }));
  const a = document.createElement('a');
  a.href = blobUrl;
  a.download = '<Имя_книги>_<BOOK_ID>.pdf';
  document.body.appendChild(a);
  a.click();
  setTimeout(() => { URL.revokeObjectURL(blobUrl); a.remove(); }, 60000);
  return { len: bytes.length };
});
```

Имя файла: cyrillic-безопасное, в формате `<Название>_<BOOK_ID>.pdf`. Название взять из `<title>` страницы карточки книги или спросить у пользователя.

## 6. Проверить результат

```bash
file "<путь>/Имя_книги_<BOOK_ID>.pdf"
```
Должно быть: `PDF document, version 1.7, N pages`. Размер должен соответствовать `len` из шага 5 (обычно 3–15 МБ).

Если файл не появился в целевой папке за ~5 секунд — проверить `~/Downloads` (CDP-настройка могла не примениться к новой вкладке) и перенести.

## 7. Следующая книга

Для каждой следующей книги повторить шаги 2–6. Браузер и сессия остаются — повторная авторизация не нужна.
</process>

<troubleshooting>
- **401/403 на documentFile** — сессия истекла. Попросить пользователя заново войти в Лань в окне браузера, либо перейти на `e.lanbook.com` и обновить токен.
- **JSON без поля `data`** — проверить, что URL содержит `base64=1`. Без него эндпоинт может вернуть иной формат.
- **Файл упал в `~/Downloads`** — CDP `setDownloadBehavior` применился не к той вкладке/сессии. Выполнить настройку на той же странице, где вызывается `a.click()`, и убедиться, что между вызовами не открывались новые вкладки.
- **PDF.js не загрузил книгу (нет `#pageTotal`)** — книга недоступна по подписке учреждения. Проверить доступ через карточку на `e.lanbook.com`.
- **Большая книга (>15 МБ base64)** — `reader.evaluate` может не вернуть base64 целиком из-за лимита сериализации. В этом случае создавать blob и триггерить скачивание внутри `evaluate`, не возвращая данные наружу (как в шаге 5).
</troubleshooting>

<security_and_ethics>
- Использовать только для книг, к которым у пользователя есть законный доступ (подписка вуза, личная покупка).
- Не обходить DRM и не распространять скачанные файлы — только для личного использования в рамках ВКР.
- JWT из URL `jwtToken=...` виден в `performance.getEntriesByType('resource')` — это нормально, он привязан к сессии пользователя и не требуется извлекать вручную. `fetch` с `credentials: 'include'` использует его автоматически.
</security_and_ethics>
